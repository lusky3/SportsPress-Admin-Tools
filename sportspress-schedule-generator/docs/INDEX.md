## 📝 Documentation Standards

### File Naming

- User guides: Descriptive names (e.g., PHASE3-USER-GUIDE.md)
- Reference docs: Topic-based (e.g., CONFIGURATION-PROPERTIES.md)
- Developer docs: Purpose-based (e.g., DEVELOPMENT-HISTORY.md)
- Archived docs: Preserve original names

### Content Structure

- Start with overview/purpose
- Include table of contents for long docs
- Use examples liberally
- Add troubleshooting sections
- Link to related documentation

### Markdown Style

- Use headers for hierarchy
- Code blocks for examples
- Tables for comparisons
- Lists for steps/features
- Bold for emphasis, not italics
