# Import League Structure and Load from SportsPress Fixes

## Issues Fixed

### 1. Import League Structure Only Adding Child Leagues

**Problem:** The Import League Structure feature was only importing child leagues/divisions, not handling the parent league properly.

**Root Cause:** The JavaScript was trying to manipulate the DOM directly, which was fragile and didn't properly handle the league structure returned by the server.

**Solution:**

- Changed the Import League workflow to save the imported data via AJAX and then reload the page
- Added new AJAX handler `ajax_save_imported_league()` that properly converts the league structure to configuration format
- The page reload ensures all sections (divisions, home venues, inter-division games) are properly populated with server-side rendering

### 2. Division Blocks Losing Function After Import

**Problem:** After importing a league, the division blocks would show teams as plain text instead of interactive checkboxes.

**Root Cause:** The JavaScript DOM manipulation was creating malformed HTML structures.

**Solution:** By reloading the page after import, the server-side PHP rendering creates proper HTML structure with all interactive elements.

### 3. Import League Creating Multi-line Text Box Instead of Multi-select

**Problem:** Teams were being displayed in a textarea instead of as a list of checkboxes.

**Root Cause:** Same as issue #2 - improper DOM manipulation.

**Solution:** Server-side rendering after page reload ensures proper checkbox structure.

### 4. Import League Not Populating Home Venues and Inter-Division Sections

**Problem:** After importing a league, the "Configure Home Venues" and "Configure Inter-Division Games" sections remained empty.

**Root Cause:** These sections are populated server-side based on the divisions data. The JavaScript DOM manipulation didn't trigger the server-side logic to regenerate these sections.

**Solution:** Page reload after import ensures all dependent sections are properly regenerated by the server.

### 5. Add Division Pre-populating with Content from First Block

**Problem:** When clicking "Add Division", the new division block would be pre-populated with the select dropdown value from the first division block.

**Root Cause:** The jQuery `.clone()` method was copying the selected state of select elements, and the clearing logic wasn't comprehensive enough.

**Solution:** Enhanced the select dropdown clearing logic to:

- Clear the value with `.val("")`
- Reset to first option with `.prop("selectedIndex", 0)`
- Remove data attributes that might store previous values
- Force the first option (placeholder) to be selected
- Handle Select2 dropdowns by destroying and reinitializing

### 6. Load from SportsPress Dropdown Locked to Previous Block Option

**Problem:** The "Load from SportsPress" dropdown in new division blocks would show the selection from the previous block.

**Root Cause:** Same as issue #5 - select element state was being cloned.

**Solution:** Same fix as issue #5 - comprehensive select dropdown clearing.

        }
    });
});

#### 4. Enhanced Add Division Button Handler (JavaScript)

Improved select dropdown clearing with proper Select2 handling:

```javascript
$("#spsg-add-division").click(function() {
    // ... clone template ...
    
    // Enhanced select clearing
    template.find("select").each(function() {
        var $select = $(this);
        
        // Destroy Select2 BEFORE clearing (if active)
        var isSelect2 = typeof $.fn.select2 !== "undefined" && $select.hasClass("select2-hidden-accessible");
        if (isSelect2) {
            $select.select2("destroy");
        }
        
        // Clear the select element
        $select.val("");
        $select.prop("selectedIndex", 0);
        $select.removeAttr("data-selected");
        $select.removeData("selected");
        
        // Force first option selected
        var $firstOption = $select.find("option:first");
        if ($firstOption.length) {
            $firstOption.prop("selected", true);
        }
    });
    
    // ... rest of clearing logic ...
    
    // Append to DOM
    container.append(template);
    
    // Reinitialize Select2 AFTER appending to DOM
    if (typeof $.fn.select2 !== "undefined") {
        template.find("select").select2({
            width: "100%",
            placeholder: "Select an option",
            allowClear: true
        });
    }
});
```

## Select2 Compatibility Fix

**Issue:** After the initial fix, the "Add Division" button stopped working when Select2 was enabled via the parent plugin settings.

**Root Cause:** Select2 needs to be destroyed before cloning and reinitialize after the cloned element is appended to the DOM. The initial fix was trying to reinitialize Select2 before the element was in the DOM.

**Solution:**

1. Destroy Select2 on the template BEFORE cloning/clearing operations
2. Clear the select element normally
3. Append the template to the DOM
4. Reinitialize Select2 AFTER the element is in the DOM with proper configuration

This ensures Select2 works correctly whether it's enabled or disabled in the parent plugin settings.
