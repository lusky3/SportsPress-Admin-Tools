# Postseason / Playoffs Scheduling — Design

**Status:** approved design, not yet planned or implemented
**Date:** 2026-09-10
**Author:** Cody (lusky3), with Claude

## Goal

`sportspress-schedule-generator` only produces a regular-season schedule: real
teams, known up front, one full `season_start`→`season_end` generation pass.
Add a postseason phase where the teams playing each game are **not** known at
schedule-generation time — they're seed placeholders resolved from regular-
season (and later, in-progress playoff) standings — while the day/time/venue
structure of the bracket can still be built and locked in well ahead of time.

Concretely, for `winter_2026-28_v1`: the configured `season_end` (2027-03-28)
currently covers 4 weeks that are actually playoffs, not regular season. The
regular season should end 2027-02-28; the last 4 weeks become a seeded,
per-division bracket.

## What exists today

- `SPSG_Schedule_Configuration` models exactly one `season_start`/`season_end`
  pair, one `games_per_team`, one `divisions[]` list. No phase/stage concept.
- `SPSG_Placeholder_Team_Manager` mints real `sp_team` posts as stand-ins
  (`create_placeholder_team()`), and `replace_team()` swaps a placeholder for
  a real team across every `sp_event`/`sp_results`/`sp_players` reference and
  the event title string. Built for the "Generic Team" round-robin filler
  feature, but the mechanism is exactly what seed resolution needs.
- `sportspress-league-manager` has no standings/tiebreak logic of its own — it
  only reads core SportsPress's `SP_League_Table::data()` output (unsorted, by
  the caller) to enumerate division membership, plus a separate one-off
  `GET /teams/compare` head-to-head tool. PIM is tracked only per-player
  (`SPLM_Penalty_Watch`, discipline digest, leaders), never aggregated per team.
- Core SportsPress (`sportspress-pro`, `class-sp-league-table.php`) already
  has more than expected, confirmed by reading the plugin directly:
  - **Priority-ordered multi-column sort.** Every stat is an `sp_column` post
    with `sp_priority` (rank) and `sp_order` (ASC/DESC) meta; `sort()` walks
    priorities in order. Reordering criteria is already a native admin UI
    (assign priority numbers) — no new UI needed for that part.
  - **Head-to-head tiebreaking** — `get_option('sportspress_table_tiebreaker')
    === 'h2h'` re-sorts only the tied teams via a mini standings recompute
    scoped to just those teams (`$this->data(false, $teams)`).
  - **Date-range and season/league scoping** (`$this->date === 'range'`,
    `tax_query` on `sp_league`/`sp_season`) — already sufficient to compute
    standings over just weeks 1-3 of a playoff round-robin.
  - No PIM column exists on the live site today (checked: OT, PTS, Tie, GP, W,
    L, GF, GA, Diff, L10, Strk). No coin-flip concept exists.
- `sp_season` is registered `hierarchical => true` (native "Parent Season"
  field) — a playoffs season as a child term of the regular season is a plain
  `wp_insert_term()` call, no new code.
- Config save/load/export already exists (`SPSG_Configuration_Manager`) —
  any postseason config, including a manually re-grouped one, is just another
  saved config using that same system.

## Bracket structure

Runs independently **per division** (confirmed: 5 divisions this season → 5
brackets, 5 champions — not one combined league-wide bracket). Generalizes to
any even division size `N` (this league's divisions are 6, 6, 6, 8, 6 — all
even; odd sizes are out of scope, see Edge cases).

Split each division's seeds 1..N into a top half (1..N/2) and bottom half
(N/2+1..N). Weeks 1 through `round_robin_weeks` (default 3) pair every top
seed against a *different* bottom seed each week — a cross round-robin. When
the bottom half has more than `round_robin_weeks` members (true whenever
`N > 6`, e.g. this league's one 8-team division), each team plays only
`round_robin_weeks` of its possible bottom-half opponents.

The pairing is generated by a cyclic 1-factorization of the complete bipartite
graph between the two halves, keeping only the **last** `round_robin_weeks`
rounds (i.e. dropping the earliest round when the bottom half is larger than
`round_robin_weeks`). For `top = [1..N/2]`, `bottom = [N/2+1..N]` (0-indexed
within each half as `t_i`, `b_j`), round `r` (0-indexed) pairs `t_i` with
`b_{(i + r) mod (N/2)}`. Using only rounds
`[N/2 - round_robin_weeks .. N/2 - 1]`, in that order, reproduces both
verified real examples exactly:

- N=6 (`round_robin_weeks = 3 = N/2`, no rounds dropped):
  `Week1: 1v6,2v5,3v4` · `Week2: 1v5,2v4,3v6` · `Week3: 1v4,2v6,3v5`
- N=8 (`round_robin_weeks = 3 < N/2 = 4`, round 0 dropped):
  `Week1: 1v8,2v5,3v6,4v7` · `Week2: 1v7,2v8,3v5,4v6` · `Week3: 1v6,2v7,3v8,4v5`

After week `round_robin_weeks`, every team has played a distinct subset of the
opposite half exactly once (no repeats, no team idle any week, both examples
verified against the real league's stated format).

**Week `round_robin_weeks + 1` (the final week):** re-rank all N teams by
their combined round-robin record (points → head-to-head → PIM → coin flip,
same cascade as regular-season standings, scoped to just this division's
round-robin games), then pair adjacent new-ranks: new-1 vs new-2
(**Championship**), new-3 vs new-4, new-5 vs new-6, ... (all remaining pairs,
collectively **Consolation**). Every team plays in the final week; nobody
sits out.

## Standings & tiebreak engine

New class in `sportspress-league-manager` (e.g. `SPLM_Standings`) that wraps
and extends `SP_League_Table` rather than replacing it:

1. Add a **PIM `sp_column`** (new — team PIM isn't tracked anywhere today).
   Its value is the sum of that team's players' `pim` stat for the events in
   scope; give it the next available `sp_priority` after points, `sp_order`
   ascending (fewer is better). Once this column exists, `SP_League_Table`'s
   own native sort already incorporates it — including on the real,
   site-visible League Table pages, not just internally.
2. Turn on `sportspress_table_tiebreaker = h2h` (native option) — already the
   right semantics (mini head-to-head recompute among just the tied teams).
3. **Coin flip** — new, since core has no concept of it. Only invoked for
   teams still tied after PIM. Decided once and persisted (e.g. as postmeta on
   the standings computation's owning object), never re-rolled on a later
   recompute, so results stay stable and auditable.
4. **Regular + playoff PIM combined** — `SP_League_Table` scopes to one
   `sp_season`/`sp_league` tax_query at a time. Rather than forking that
   query, sum the PIM column separately for the parent (regular) season and
   the child (playoff) season and add them, only for the PIM criterion
   specifically — points, wins, etc. stay correctly scoped to whichever
   single season is being ranked (regular-season standings for initial
   seeding; round-robin-only standings, via `SP_League_Table`'s existing
   date-range mode, for the week-4 re-seed).
5. Criteria order is **admin-editable** the same way core already allows —
   assign `sp_priority` numbers to columns. `SPLM_Standings` doesn't need its
   own separate reordering UI for points/PIM; it only needs to teach the
   admin UI how to express "head-to-head" and "coin flip" as reorderable
   steps in that same list (since those two aren't plain columns), and how to
   remove/re-add them.

`SPLM_Standings::rank( $team_ids, $season_id, $date_range = null )` is the one
entry point both the regular-season seeding step and the week-4 re-seeding
step call — the only difference is which season/date-range is passed in.

## Seed placeholder resolution

Two resolution events, both using the existing `SPSG_Placeholder_Team_Manager`
(mint per-division placeholders — `"Div 1 Seed 1"` .. `"Div 1 Seed N"` for
weeks 1..`round_robin_weeks`, `"Div 1 RR-Seed 1"` .. `"Div 1 RR-Seed N"` for
the final week — then `replace_team()` swaps in the real team):

1. **Regular season ends** → `SPLM_Standings::rank()` over the full regular
   season, per division → resolve that division's `Seed 1..N` placeholders.
2. **Round-robin weeks conclude** → `SPLM_Standings::rank()` over just those
   weeks' games, per division → resolve that division's `RR-Seed 1..N`
   placeholders (which determines the final week's Championship/Consolation
   pairings).

Both steps can run in two modes, **manual by default, automatic optionally
enabled**:

- **Manual:** an admin action ("Resolve Seeds") the user triggers once they've
  confirmed the relevant results are final.
- **Automatic:** triggered by detecting that every game in the relevant range
  has a completed score. A forfeit/cancelled game counts as decided, not
  missing, so one dead game can't block auto-resolution indefinitely.

Both are idempotent — re-running resolution against a placeholder that's
already been resolved is a no-op, so a late score correction and a
re-trigger (manual or automatic) doesn't error.

## Config & scheduling integration

The postseason is a **separate `SPSG_Schedule_Configuration`**, not an
extension of the regular-season one:

- Its own `season_start`/`season_end` covering just the playoff weeks.
- Linked to the same league via a real hierarchical `sp_season` child term
  (e.g. "W2026-27 Playoffs" as a child of "W2026-27") — `wp_insert_term()`
  with `parent` set, no new taxonomy code.
- Reuses the regular season's venues.
- Its `divisions[]` (team groupings) **default to a copy of the regular
  season's divisions**, but are freely editable before the bracket is
  generated — this is also the answer to "advanced regrouping": since the
  postseason config is already its own saved/exportable config (reusing
  `SPSG_Configuration_Manager`, same as any other config), a manually
  re-grouped structure (e.g. splitting 6/6/6/8/6 into 4/4/4/4/4/4/6, named
  Group A-G) *is* the saved config — no separate "template" system needed.
  Seeding within any custom group uses that team's regular-season standing
  regardless of which original division it came from.
- New settings: `round_robin_weeks` (default 3), `championship_day` (day of
  week + time window, e.g. Friday 6-9pm), `consolation_day` (day of week, no
  time restriction), `seed_resolution_mode` (`manual` | `automatic`).
- Two new allocator-facing constraints not needed for the regular season: (a)
  a day-of-week carve-out so all divisions' Championship games land on one
  specific day and all other final-week games land on another, and (b) a
  time-window constraint that applies only to Championship games.

## Edge cases

- Odd-sized divisions (not splittable into equal top/bottom halves) are out
  of scope for v1 — this league's divisions are all even.
- A tie surviving points → H2H → PIM goes to a persisted coin flip; ties are
  re-evaluated fresh each computation, never read from a stale cache.
- Auto-resolution treats a forfeited/cancelled game as decided, not missing.
- Re-running seed resolution against an already-resolved placeholder is a
  no-op.

## Testing

Following this repo's existing standalone-PHP-test conventions
(`ReflectionClass::newInstanceWithoutConstructor()` bootstrap pattern):

- Pairing-table generator: exact assertions for both real examples (N=6,
  N=8) plus at least one more synthetic even size, to confirm the cyclic
  construction generalizes rather than being special-cased.
- `SPLM_Standings::rank()`: one test per tiebreak criterion in isolation, one
  combined cascade test, one for the persisted (not re-rolled) coin flip, one
  for regular+playoff PIM summation.
- Seed resolution: both triggers (manual action; automatic score-completion
  detection, including the forfeit-counts-as-decided case), plus the
  idempotent-re-run case.
- Full suite (`bash run-all-tests.sh`) and `python3 -m lizard -C 8 -L 50`
  stay green throughout, per this repo's standing convention.

## Suggested implementation phasing

This is one cohesive design but naturally splits into sequential PRs:

1. `SPLM_Standings` (PIM column + coin flip + combined-PIM + `rank()` entry
   point), independent of anything schedule-generator-side.
2. Pairing-table generator + its tests (pure function, no WP dependencies).
3. Postseason config schema (divisions default-copy, new settings) + child
   `sp_season` creation.
4. Seed placeholder minting/resolution (both triggers) wired to
   `SPLM_Standings`.
5. Championship/consolation day + time-window allocator constraints.
6. Admin/React dashboard UI for all of the above.
